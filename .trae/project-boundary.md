# 当前项目边界

本文件定义当前一期项目的**业务、算法、设备、数据和技术实现边界**。知识库中其他 `roadmap` 内容仅用于扩展设计和领域补充，不自动进入本期交付范围。

## 一、项目目标

当前项目建设一套围绕足球运动员持续数据管理的运动员训练数据管理系统，以统一运动员标识为主线，完成从运动员档案、测试任务、测试结果、专项计算、健康状态、生长发育、趋势分析到个人/团队报告的业务闭环。

系统服务于体能师、康复师、队医、主教练、科研人员等角色，并通过 RBAC 权限控制不同岗位的数据查阅、修改和报告使用范围。

## 二、本期必须交付的业务能力

### 1. 组织与运动员数字档案

本期支持：

- 机构、队伍、小组与运动员的基础组织关系。
- 运动员唯一标识。
- 同一运动员关联主队伍及多个专项/恢复小组。
- 基础信息、基础体态、专项测试、生长发育、RTP 状态、医疗康复附件、历史趋势及报告的统一入口。
- 关键数据保留时间、操作者和来源信息，满足查询和基础审计需要。
- 基础数据支持手工维护和标准模板导入。

本期目标是形成“一人一档”的持续数据归集，不扩展为完整的人事、合同、保险、学籍或家长管理系统。

### 2. RTP 红黄绿参训状态管理

本期支持：

- 红：不建议训练。
- 黄：限制参训并控制训练量或科目。
- 绿：正常全量训练。
- 授权康复师人工确认和修改状态。
- 记录状态原因、训练限制和下次复核日期。
- 状态保存后立即在系统界面生效。
- 保留状态变更前后值、操作人、时间、原因和限制内容。
- 其他角色按 RBAC 权限查看。

**本期不由系统自动作出医学判断，不根据算法自动升降 RTP 状态。**

### 3. PHV 生长发育监控

本期支持录入：

- 年龄
- 站立身高
- 坐高
- 体重
- 父母身高等必要数据

系统通过版本化公式计算并保存：

- 成熟度偏移
- 预计 PHV 年龄
- 预测成年身高
- 历次测量与成长趋势

公式需记录适用性别、输入字段和算法版本。

PHV 结果用于成长跟踪、训练分组和选材辅助，**不作为医学诊断或单独选材结论**。

### 4. 多维指标矩阵库

本期建立可配置指标库，覆盖：

- 身体形态
- 身体机能
- 身体素质
- 健康风险筛查

每项指标至少可配置：

- 名称
- 分类
- 单位
- 数据类型
- 参考范围
- 采集方式
- 有效版本

主测人员可勾选指标，指定目标小组、责任人和执行时间窗口，形成测试任务。

### 5. 足球专项测试模型库

本期至少支持：

- Yo-Yo 间歇恢复测试
- RSA 多次冲刺能力测试
- 伊利诺伊敏捷测试
- 带球绕杆/改良敏捷测试

每个测试模型记录：

- 测试规程
- 记录字段
- 单位
- 有效性规则
- 派生算法
- 算法版本

测试结果支持手工录入和 CSV/标准模板导入。RSA 等明确的派生指标由系统按照确认后的公式计算。

参考范围支持按性别、年龄组、队伍和模型版本配置；演示或项目内参考区间不表述为普遍适用的行业常模。

### 6. 设备结果接入

当前设备接入目标是将**测试结果**可靠进入系统，而不是建设设备控制平台。

本期允许的数据入口：

- 手工录入
- CSV/标准结果文件导入
- 具备明确开放条件并经联调验证的厂商 API/适配器

计时门、测力台等智能硬件只有在设备商提供正式接口、文档和必要联调条件后，才进入接口实施范围。

### 7. 多设备结果级组合计算

本期支持将不同测试环节或设备产生的**结果数据**按运动员、测试批次进行关联，在数据齐备后执行组合运算。

组合模型可配置：

- 组成指标
- 单位
- 数据来源
- 计算公式
- 权重
- 参考组
- 算法版本

系统展示原始值、派生分和参考版本，保证计算过程可复核。

**本期不要求不同设备的原始信号实时同步，也不依赖统一采集时钟。**

### 8. 测试任务与执行进度看板

本期支持：

- 测试任务创建和下发。
- 目标小组/成员。
- 主测责任人。
- 执行时间窗口。
- 待开始、进行中、已完成等任务状态。
- 已测人数、目标人数和完成率。
- 成员级已测/未测情况。
- 手工录入或 CSV 导入结果后自动更新任务进度和运动员测试时间线。

### 9. 趋势与报告

本期支持个人和团队报告。

报告可包含：

- 当前指标值
- 参考范围
- 状态判定
- RTP 状态
- 组合指数
- 专业人员记录
- 历次测试结果
- 近 N 次趋势

支持 PDF 导出，并记录报告生成时间和版本。

“自动生成”仅指系统按照既定模板组装已有数据和规则结果，**不等于自动生成训练处方或医学建议**。

### 10. 医疗康复资料归档

当前项目的医疗能力定位为**资料归档与运动员档案关联**。

本期支持：

- PDF
- 图片/扫描件
- 医疗或康复相关附件

资料与运动员档案关联，并由 RBAC 控制查阅范围。

本期不将医疗模块扩展为完整医院 EMR/PACS 系统或完整临床诊疗流程。

### 11. RBAC 权限

本期至少覆盖体能师、康复师、队医、主教练、科研人员等角色，根据岗位控制：

- 数据查看
- 数据录入/修改
- 报告查看/导出
- RTP 状态修改等特定操作

权限的目标是满足当前业务隔离和敏感资料最小可见原则，不要求在一期实现复杂工作流权限平台。

### 12. 私有化部署

系统采用前后端分离的 B/S 架构，浏览器作为统一操作入口。

当前技术基线：

- 前端：Web 前端，负责组织管理、数据录入、任务看板、图表和报告交互。
- 后端：Java Web，负责业务规则、权限、数据持久化、文件归档、报表与接口适配。
- 结构化数据：MySQL。
- PDF、图片等大文件：本地文件存储、NAS 或采购方指定对象存储。
- 部署：采购方本地服务器或私有云环境。

核心运动数据和医疗附件保存于采购方指定环境。

## 三、本期明确不承诺的能力

以下内容即使在知识库中存在，也不属于当前项目默认交付边界：

1. 基于 ACWR、训练负荷、睡眠、伤病史等因素的自动 RTP 风险判定。
2. 自动医疗诊断、自动复出许可、自动训练处方。
3. sRPE、TRIMP、GPS 训练负荷管理和完整周期化训练计划系统。
4. 设备 BLE/Wi-Fi 底层协议控制、原始事件流或原始信号实时采集。
5. 多设备统一时钟同步和原始曲线级实时融合。
6. 自动工位排程、复杂设备生命周期管理、心跳监控、校准管理和固件 OTA。
7. OCR/DICOM 解析、医院 HIS/EMR/PACS 深度接口和完整医疗康复工作流。
8. AI 选材、AI 训练建议、自然语言问答等 AI 产品功能。
9. 家长端、完整移动协同/审批平台等独立业务系统。
10. 跨项目（篮球、田径等）产品化模板体系。
11. 将项目内参考范围宣称为普遍适用的行业常模。

上述能力只有在后续明确变更项目范围、满足外部接口条件并确认工作量后，才能转入当前交付范围。

## 四、设备接口的特殊边界

设备接口必须满足以下条件才可认定为本期可实施：

1. 厂商明确允许第三方接入。
2. 提供正式 API、SDK、标准结果文件或其他可验证接口。
3. 提供必要的账号、授权、设备或测试环境。
4. 完成实际联调验证。

如果以上条件不具备，系统仍通过手工录入或 CSV/标准结果文件完成业务闭环，不能因为设备厂商未开放接口而将“直接实时控制设备”视为软件缺陷。

## 五、算法边界

系统负责将已确认的公式、参考规则和组合模型进行软件化实现，并保留版本。

对以下内容不作无依据承诺：

- 医学有效性
- 绝对预测精度
- 通用行业常模
- 未经确认的设备厂商算法
- 自动训练或医疗决策

涉及 PHV、RSA、组合指数等算法时，应保存输入、输出、公式版本和参考口径，使计算结果可复核。

## 六、验收边界

当前项目的验收对象是**软件业务闭环是否完整可运行**，重点包括：

- 数据能够录入/导入并持久化。
- 运动员档案能够完整关联当前项目要求的数据。
- RTP 状态可按权限维护并留痕。
- PHV 和专项测试可按照确认公式计算。
- 测试任务可下发、录入结果并自动更新进度。
- 组合结果可计算和复核。
- 趋势和报告可展示并导出 PDF。
- 权限能够隔离不同角色操作。
- 系统可在采购方指定环境部署运行。

外部硬件直接实时控制、专业医学判断和扩展平台能力，不作为当前项目基础验收条件，除非后续形成明确的范围变更记录。

## 七、边界变更规则

后续新增需求如果出现以下任一情况，应视为范围变更而不是当前项目自然延伸：

- 新增独立业务域。
- 新增一种需要专项联调的第三方设备或系统。
- 从结果级接入升级到原始信号/实时控制。
- 从人工业务判定升级为自动风险或决策模型。
- 引入新的客户端形态并形成独立业务流程。
- 新增重大算法、数据标准或监管要求。

范围变更应单独记录目标、接口条件、数据口径、验收标准和实施安排。
